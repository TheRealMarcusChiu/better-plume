# Plume

A multiplayer underwater micro-organism game. Up to 10 players navigate luminous segmented creatures through a deep-sea world, eating glowing food to grow longer while avoiding other players.

## Features

- **WebRTC peer-to-peer multiplayer** — no backend server required
- **Host-authoritative simulation** at 30 Hz; snapshots broadcast ~12 Hz to guests
- **Beautiful underwater aesthetic** — deep navy sea, animated caustic light currents, drifting plankton, glowing segmented organisms with curling tendrils
- **Up to 10 players** with enforced unique names and distinct colors
- **Grow by eating food** — die when your head hits another player's body
- **Spawn protection**, safe spawning, fair head-on deaths
- **Smooth camera**, bounded large world (4000×4000), bottom-right minimap
- **Mouse, keyboard, and mobile touch steering**
- **Shareable room URL** — share via room code or copy link button

## Quick Start

```bash
npm install
npm start          # serves at http://localhost:8080
```

Open the page, click **Create room**, enter your name, and share the room code or link with others. They click **Join room** and enter the code.

## Multiplayer Architecture

The game uses **PeerJS 1.5.5** (vendored as `peerjs.min.js`) over the **public PeerJS signaling server** (`0.peerjs.com`).

### Protocol

```
Guest → Host: { t:'hello', name }
Host → Guest: { t:'welcome', id, color, name, snapshot } | { t:'error', message }
Host → Guest: { t:'snapshot', tick, players, food, bursts }  (~12 Hz)
Guest → Host: { t:'input', angle }  (~30 Hz)
Guest → Host: { t:'respawn' }
Host → Guest: { t:'ping' } / Guest → Host: { t:'pong' }
Host → Guest: { t:'end', reason }
```

### Important Constraints

- **No TURN server** — direct P2P connections only. Some corporate firewalls/symmetric NATs will block connections. Players on the same network or with open NATs work best.
- **Host lifetime** — the room exists only as long as the host's tab is open. If the host leaves or refreshes, all guests are disconnected.
- **Public signaling** — PeerJS's free signaling service is used. For production, host your own signaling server.

## Running Tests

Tests use Playwright and require starting a local PeerJS signaling server automatically.

```bash
npm test                  # all 23 tests
npm run test:engine       # 11 engine behavioral tests
npm run test:e2e          # 12 WebRTC multi-context tests
```

Test evidence (screenshots) is saved to `screenshots/`.

### Test Coverage

**Engine behavioral tests** (no network required):
- Eat food → body grows + score increments immediately
- Head hits other body → attacker dies, food scattered along body
- Head-on collision → both players die
- Spawn protection prevents death during protection window
- Duplicate names rejected (case-insensitive, whitespace-trimmed)
- 10-player cap enforced
- All 10 players receive distinct colors
- Invalid angles (NaN, Infinity) ignored by input validator
- Dead player inputs ignored
- Respawn restores player with fresh score and spawn protection

**WebRTC multi-context tests** (uses local PeerJS signaling):
- Host creates room with 6-letter code
- Guest joins via room code; both see canvas
- Guest joins via `?room=` URL parameter (shareable link)
- Duplicate name rejected with error message
- All connected players have unique colors
- Guest inputs are authoritative (position changes on host)
- Death triggers dead screen; respawn button restores game
- Late joiner receives current game snapshot with all players
- Host leaving → guests see "room ended" message
- Minimap rendered with non-blank canvas content
- Mobile viewport: landing and HUD usable at 390px width
- Touch steering: no crash, game continues running

### Test Hooks

Game exposes `window.__plume` only when `?test=1` is in the URL, giving access to the engine instance, player state, and control functions.
